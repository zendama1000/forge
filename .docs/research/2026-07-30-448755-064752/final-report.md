## 1. エグゼクティブサマリ

本調査は「A/B 2方式のセールスレター生成システムを作れるか」ではなく、**「A/B 比較が実験として成立するか」**を軸に据え直した上で、実機実測（CLI 2.1.220）で round1 の推測ベース結論を上書きした。結論は次の5点に集約される。

### 1.1 結論の骨格

1. **呼出層の統制は完全に可能で、鍵は「`--allowed-tools` は封じ込めではない」こと。**
   公式リファレンスは `--allowed-tools` を「プロンプトなしで実行されるツール」と定義し、可用性の制限には `--tools` を使えと明記している。実機で `--tools ""` + `--permission-mode bypassPermissions` + `--output-format json` が exit 0・`permission_denials` 空・`structured_output` 返却で成立し、テキスト生成のみの本実験は**ツールゼロで完全に走る**。これ1つで (a) 許可プロンプト待ちの無人ハング、(b) `references/` への Write、(c) arm 越境 Read、(d) 構造的なループ上限、の4問題が同時に閉じる。

2. **公平性の破れは予算だけでなく「呼出単位のすべて」に及ぶ。**
   `--max-budget-usd` は per invocation（サブエージェント支出込み・print 限定）であり、同一値 n は A=n / B=8n の非対称になる。しかも非対称は3系統に増えた — 予算・外部 wall-clock タイムアウト・呼出あたり固定文脈オーバーヘッド。揃えるべきは **per_run 総量**であり、per_call 値はそこから導出する。

3. **既存ハーネス資産は骨格として使えるが、2つの実害バグを抱えている。**
   (i) コスト/トークン計上が debug ログ grep 方式のため現行 CLI で 0 件ヒットして沈黙、(ii) 予算超過分類が旧文言依存で素通りし、決定的失敗を retry_with_backoff が再試行して支出を積み増す。両方の正しい情報源は `--output-format json` のエンベロープだが、`run_claude` はそれを成功時も失敗時も `rm` している。

4. **最悪の失敗は「壊れたと分からない」経路に集中する。**
   incomplete-response 挙動（切断時に完了済み出力＋通知文を返す）、`--json-schema` 失敗時の `.result` 生テキストへの静かなフォールバック、幹マッピングの静かな腐敗、監査連鎖の断裂。対策は一貫して **fail-closed ゲートと消えない台帳**であり、新機能ではない。

5. **実験としての成立性が最も弱い環。**
   N=3 では符号検定の最小両側 p=0.25 で有意性が原理的に到達不能。記述的パイロットとしてのみ成立し、「有意」「優位」「非劣性」を使わない事前合意が必要。加えて `claude -p` は既定で CLAUDE.md・`.claude/rules`・auto memory・hooks・MCP を自動発見するため、**幹以外の不可視入力が混入する**。

### 1.2 コスト構造の重要な訂正

round1 の見積り（B/A ≒ 1.08倍）は誤りで、**B/A ≒ 4〜7倍**。支配項は幹の反復注入（入力・$5/MTok）ではなく、**思考を含む出力（$25/MTok）を8回払うこと**。幹を 30K→100K に増やすと比率は逆に縮む。

## 3. 実機実測で確定した事実（CLI 2.1.220 / Windows）

これが本調査の最大の成果である。round1 は公開ドキュメント・二次情報ベースだったが、round2 で haiku/sonnet の実呼出により以下を一次実測した。

### 3.1 フラグの実在と挙動

| フラグ | 実測結果 |
|---|---|
| `--tools ""` | **成立**。exit 0 / `subtype=success` / `structured_output` 返却 / 実ツール呼出 0（3視点が独立確認） |
| `--allowed-tools` | 公式定義は「プロンプトなしで実行されるツール」＝**封じ込めではない**。可用性制限は `--tools` を使えと明記 |
| `--permission-mode` | `bypassPermissions` / `dontAsk` が choices に実在。`--dangerously-skip-permissions` は `bypassPermissions` と等価 |
| `--max-budget-usd` | **per invocation**（「Per invocation (applies to the current run)」「Spend from subagents counts toward the cap」）。累積予算フラグは存在しない |
| `--json-schema` | Constrained Decoding として動作、`structured_output` を返す |
| `--max-turns` / `--system-prompt-file` | **実在**（argument-missing プローブで確定）。既存ハーネスの `--help` grep 方式は**偽陰性**を返していた |
| `--bare` | **使用不能**。`Not logged in · Please run /login`（keychain 読取をスキップし `ANTHROPIC_API_KEY` が必要。本環境はサブスク OAuth） |
| cache 制御 | `cache_control` / breakpoint 相当のフラグは **help に存在せず**。キャッシュ配置は自動任せで制御不能 |

### 3.2 JSON エンベロープの実フィールド

```
total_cost_usd / modelUsage[model].{inputTokens, outputTokens, cacheCreationInputTokens, costUSD}
usage.{input_tokens, cache_creation_input_tokens, cache_read_input_tokens, output_tokens}
num_turns / session_id / uuid / subtype / terminal_reason / permission_denials / errors
duration_ms / duration_api_ms / stop_reason / is_error / type
```

**重要な注意点**:
- `usage.input_tokens` が **0** で `modelUsage.*.inputTokens` が実値（522）→ **トークン集計は `modelUsage` を権威とする**
- ロードされた tools / mcp_servers / plugins / CLAUDE.md 系の**申告フィールドは無い** → 入力対称性の検証には `stream-json` の `system/init` メッセージが必要（DA-011）

### 3.3 予算超過の実挙動

| 項目 | 実測値 |
|---|---|
| exit code | **1**（既存ハーネスが期待する 21 ではない） |
| subtype | `error_max_budget_usd` |
| terminal_reason | `budget_exhausted` |
| errors | `[Reached maximum budget ($X)]` |
| 旧文言 `Exceeded USD budget` | **0件（出現しない）** |

→ 既存の `classify_run_claude_exit` は文言 grep なので**素通りし、`is_retryable` が真になって決定的失敗を再試行し支出を積み増す**。分類は文言ではなく `subtype` / `terminal_reason` を一次キーにすべき。

### 3.4 固定文脈オーバーヘッド

| 条件 | total_cost_usd | cache_creation |
|---|---|---|
| 既定文脈（同一の些末プロンプト） | $0.01701 | 7,864 tok |
| `--system-prompt` + `--setting-sources` 空 + CLAUDE.md 無し cwd | $0.00198 | 0 |
| **比** | **8.6倍** | — |
| 別環境での単発呼出 | $0.1438 | 23,694 tok |

固定費は**呼出回数に比例する**ため、per_run 総額を単純に8分割すると B の実作業予算を過小配分する。
※ この比較は system-prompt / setting-sources / cwd の3変数を同時に変えた測定であり、寄与の切り分けは未実施（DA-011）。

### 3.5 幹 read-only の実効性（OS 手段は補助にすぎない）

| 手段 | 実測結果 |
|---|---|
| `attrib +R` | in-place 上書きは防いだが **`rm -f` は通った** |
| `icacls` ディレクトリ単層 deny | 新規作成のみ防ぎ、**既存ファイルの上書き・削除は通った** |
| `icacls /T` 再帰 deny | 有効（Git Bash では **`MSYS_NO_PATHCONV=1` 必須** — `/deny` が `C:/Program Files/Git/deny` に誤変換された実測あり） |

→ **三層構成**に確定: 一次=ツール除去（書く道具自体を与えない） / 二次=`icacls /T` / 三次=ラン前後の sha256 マニフェスト再照合（終了時照合の一致を `status=complete` 確定の前提条件に置く）。

### 3.6 その他の実測

- Opus 5 実効スループット **約54 tok/s** → A の思考込み単一呼出（出力30K超）は **630秒** で既定600秒を超え **exit 124** で落ちる。B の各呼出は約333秒で余裕
- 環境: `jq 1.7.1` / GNU `timeout 8.32` / `sha256sum` / `node v22` / `python 3.13` すべて利用可能
- 課金形態: `ANTHROPIC_API_KEY` 未設定＝**サブスクリプション OAuth**
- auto memory は **git リポジトリ単位で全 worktree が共有**される → worktree 分離だけでは入力独立性が確保されない
- stdin は 2.1.128 以降 **10MB 上限**。2.1.211 より前の Windows は stdin 読取不能。`--system-prompt` に argv で長文を渡すと **CreateProcess 約32,767文字上限**に当たる → `--system-prompt-file` を使う
- `--tools ""` 下でも**プロンプトが読書を指示すると擬似 `function_calls` テキストが本文に混入する**。遮断成功の証拠は `permission_denials` 空ではなく **`tool_use` 件数 0**

## 4. 推奨設計（Primary）

**方針**: 「測定装置は単一実装で共有・方式内容のみ分離」＋「fail-closed ゲートと消えない台帳」を骨格に据え、段階0→3で構築する。

### 4.1 段階0: 骨格・不変条件・プローブ（実 opus 呼出 0 回。haiku/sonnet の最小プローブは必須）

**(1) 公平性 config を単一宣言 JSON にする**

| フィールド | 内容 |
|---|---|
| `model` | 既定 opus、切替可 |
| `effort` | **per-call parity**（A/B 同一レベル固定） |
| 予算 | `scope: per_call \| per_run` を**必須フィールドとして型付け** |
| タイムアウト | arm 別正規化値 |
| リトライ上限 / 並列度 / 出力長上限 | 型付き宣言 |

per_call 値の導出: `per_call = R / K + 実測固定オーバーヘッド × 安全係数`（R=per_run 総額、K=呼出回数）。
**真のラン上限はランナーが各エンベロープの `total_cost_usd` を累積して強制する**（フラグに依存させない）。

**(2) 共通 CLI テンプレート**

```bash
claude --model <id> -p \
  --system-prompt-file <f> \
  --setting-sources '' \
  --strict-mcp-config \
  --tools '' \
  --disallowedTools 'mcp__*' \
  --permission-mode bypassPermissions \
  --no-session-persistence \
  --output-format json \
  [--json-schema <s>] \
  --max-budget-usd <導出値> \
  --effort <e> \
  --debug-file <log>
```

- 全呼出を **GNU `timeout`** でラップ
- `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`
- **CLAUDE.md / `.claude/rules` の無い専用 cwd** で実行
- プロンプトはすべて **stdin または `--system-prompt-file`** 経由（argv 長を消費しない）
- ※ `--permission-mode` は実測済みの `bypassPermissions` を既定に置く（DA-013 の指摘を反映）

**(3) ランナーをベンダリング（pin コピー）する**

`common.sh` から `run_claude` / `build_per_call_guard_args` / `classify_run_claude_exit` / `validate_json` / `jq_safe` / `log` の最小集合と `simulator.sh` 全体をコピー。**コピー時の必須修正**:

| # | 修正内容 |
|---|---|
| (a) | コスト/トークンを debug ログ grep から `--output-format json` エンベロープ（`total_cost_usd` / `modelUsage`）へ |
| (b) | 予算超過分類を文言 grep から `subtype=error_max_budget_usd` / `terminal_reason=budget_exhausted` へ（`exit 124` も実装由来失敗として明示分類） |
| (c) | 状態ファイルパスを実験リポ配下へ |
| (d) | **エンベロープと失敗時出力を `rm` せず保存**し stderr も残す |
| (e) | フラグ実在プローブを `--help` grep から **argument-missing 方式**へ置換 |
| (f) | simulator の fault マッチキーを arm/theme/trial/stage まで拡張（DA-015） |
| (g) | simulator の録画トークン（`sim_parse_tokens`）もエンベロープ由来化（DA-015） |

`claude --version`（2.1.220）とベンダリング元コミットハッシュを manifest に刻む。

**(4) プローブで確定する項目**

エンベロープ実フィールド / `--tools ""` の成立と `tool_use` 0件 / 大容量 stdin 往復（10MB 上限）/ 固定文脈オーバーヘッド実測値 / 日本語見出し抽出精度と一意性 / `API_TIMEOUT_MS`・`CLAUDE_CODE_MAX_OUTPUT_TOKENS` の実効値（DA-010）/ `stream-json` の `system/init` による両腕の実効設定差分ゼロ assert（DA-011）

### 4.2 段階1: 幹写像・監査基盤（ダミー幹で E2E）

**(5) 幹写像 config — ハイブリッド方式**

| 要素 | 内容 |
|---|---|
| 主キー | `ref_kind = heading_anchor` — **生の見出し文字列**（slug ではない。github-slugger の重複連番で指す先が黙って変わる） |
| 検証1 | セクション本文の正規化 sha256（CRLF 除去後） |
| 検証2 | 引用先頭末尾数語 |

**プリフライトは2層とも fail-closed（exit 非0）**:
- 参照一意性（0件=消失 / 2件以上=曖昧）
- 内容ドリフト（sha256 不一致）
- **双方向検査**: 全工程が参照するセクション集合と幹の全セクション集合を突合し、未参照（切り出し漏れ）と二重参照（重複注入）を検出
- 解決結果が空・極端に短い場合も別失敗として検出

幹は実験期間中 **revision pin で凍結**し、改訂は人間の再承認（`expected_sha256` 再生成手順を記録）。

**(6) 成果物と台帳**

| 成果物 | 形式 | スキーマ強制 |
|---|---|---|
| 散文本文（工程3本文、工程5リライト後、工程6最終） | `.md` | **課さない**（自由生成） |
| manifest / 布石台帳 / 検査表 / 差分表 | JSON | **ajv 等の実バリデータでハードゲート** |

`validate_json` は **CRLF/フェンス衛生器にとどめる**（型検証器ではない）。

**ディレクトリ**: `runs/<run_id>/<a|b>/<theme_key>/t<NN>/s<K>/a<M>/`（attempt スコープで**不変・上書き禁止**）

| 規則 | 値 |
|---|---|
| `run_id` | `20260730-184323` 形式（Windows はコロン不可） |
| arm | `a` / `b` の1文字 |
| `theme_key` | ASCII 小文字 `[a-z0-9-]` に正規化・24文字上限、非 ASCII は削除して 8文字 sha256 接頭を付す |
| content address | sha256 **先頭16 hex** に短縮（全長は manifest に保持） |
| 相対パス長 | **80文字以内**を段階0テストでアサート |
| Git 管理 | `runs/` は **`.gitignore`**（manifest と 50MB 未満の圧縮アーカイブのみ commit）。`core.longpaths=true` を前提条件チェックに |

**インデックス JSONL**: 追記のみ＋ハッシュ連鎖（`seq` / `prev_hash` / `hash`）。1行 = 1呼出:

```
run_id, arm, theme, trial, stage, attempt, call_seq, parent_artifact_sha,
model_id, effort, flags_hash, prompt_sha256, artifact_path,
exit_code, subtype, terminal_reason, retry_count,
usage 4分類, total_cost_usd, duration_sec, log_path
```

本体（プロンプト全文・生応答・エンベロープ・debug ログ）は別ファイル。**失敗呼出とリライト中間版も削除しない**（v1 を確定してから v2 を書く。in-place 禁止）。

### 4.3 段階2: A/B 実装

**(7) 隔離設計**

| 層 | 扱い |
|---|---|
| 共有（測定装置） | 純関数の読取ユーティリティ＋追記専用 writer＋`claude -p` ラッパのみ |
| 分離（方式固有） | プロンプト、工程定義、成果物ディレクトリ |
| 機械強制 | 共有層に arm 固有語が現れないことの grep ゲート / env allowlist（`_RC_*` 等の持ち越しを明示 unset）/ arm 別 `TMPDIR` / 全パスを cd 前に絶対化し成果物が期待ディレクトリ配下にあることを事後アサート |

> **ロック解釈の明記**: 「相互隔離」は A/B の**方式内容**（コード・プロンプト・中間成果物・出力）に関する要件であり、**測定計器の共有は隔離違反ではない**。ランナー複製は MMLU の独立3実装がスコア食い違いと順位逆転を起こした前例が示す通り、方式効果と実装差を交絡させる。

**(8) B の決定的停止規則**（工程は6のまま。追加は規則のみ）

| 工程 | 停止規則 |
|---|---|
| 工程5（リライト） | 検査表の**未解消項目数が 0 になったら停止**、さもなくば**最大2パス**で打ち切り（数え上げのみでスコアリングを含まない） |
| 工程6（削除） | **1パス限定** ＋ ①布石台帳の全 ID が最終本文から被参照（grep 検証）② 事前宣言した文字数下限（削除前長の X%）を下回らない。いずれか違反ならその削除案を破棄し削除前版を最終とする |

**検査表スキーマ**: `additionalProperties: false` ＋ 禁止プロパティの静的ゲート（`score` / `rating` / `points` / `grade` / `verdict` / `pass` / `fail` / `rank` / `overall` / `total`、および number 型の評価的フィールドの不在）。中身は「理論の該当観点 ID」「該当箇所の引用」「未解消かどうかの真偽」のみ。

**(9) A は「誠実な最強の一発生成」**

- A の単一プロンプトは **B の6工程の指示内容の合併集合**（宣言文設計・構造設計・本文生成要件・検査観点の全項目・リライト方針・削除方針）を単一呼出内の手順として内包
- 幹は A には**全文**を stdin/`--system-prompt-file` で与える（B はセクション注入）
- 出力長・構成の粒度指示も B の各工程の要求水準を合算して与える

**藁人形回避チェックリスト（段階3の公平性アサートに接続）**:

| # | 検証項目 |
|---|---|
| 1 | ルール数対応表（A の命令文・制約文の個数 対 B の6工程合計） |
| 2 | 幹の実効注入トークン量（A: 全文1回 / B: セクション累計） |
| 3 | 出力長要求の一致 |
| 4 | 両腕に同一の**検証可能なダミー順守指示**を植え、順守率を機械検出（＝指示が実際に効いていたかの実測） |
| 5 | length-matched の記録（中性フィラーで埋める操作はせず、**差を数値として報告**） |

> 「指示強度」には確立した尺度が無いため**等価性は主張せず**、上記の対応表を出して非等価を脅威として明記するのが誠実な下限。

### 4.4 段階3: 確定ゲート・較正・実験

**(10) ラン単位アトミック確定**

`status=running` で開始 → **確定ゲート全通過** → `temp + fsync + rename + fsync(dir)` で `status=complete`。**解析は complete のみ**。

確定ゲートの内容:
- 期待呼出数一致
- 全 exit 0
- **incomplete 通知なし**（構造フィールド `subtype` / `is_error` / `stop_reason` で判定し、文言は二次防御）
- `output_tokens` が上限の一定割合未満
- schema フォールバックなし
- **成果物純度検査**（擬似 `function_calls` 混入なし）
- **`tool_use` 件数 0**
- ラン前後の幹 sha256 一致
- リトライ回数記録

除外は**理由コード付きで必ず台帳に残す**（サイレント除外禁止）。

**(11) 開発ループのコストゼロ化**

`FORGE_DRY_RUN` → 1回録画 → `replay`（API コスト実質ゼロ）＋ fault injection（429 / budget / timeout / malformed / empty / exit_1 / quota）で無人モードの故障処理を無料検証。replay 主キーに **arm/theme/trial/stage** を追加。合成中は `RC_REPLAY_STRICT=0`。

**(12) 較正ラン**

実幹 × 各 arm 1回（opus）でタイムアウト・per-call 実額・出力上限・所要時間を確定してから本実験。A のタイムアウトは **想定最大単一呼出出力 ÷ 52 tok/s × 安全係数2** で arm 正規化。

**(13) 実験計画**

| 項目 | 内容 |
|---|---|
| 規模 | **K≧3 テーマ × n≧3**（予算許容なら n=5）の完全ペア |
| 実行順 | **A,B,B,A 型インターリーブ**で同一時間窓に閉じ込め、逐次実行 |
| 報告 | **ITT（失敗計上）＋ per-protocol（実装由来失敗を事前定義して除外）の二重**、CONSORT 相当の除外フロー図 |
| 主要指標 | 完走率 / 所要時間 / 生トークン / 失敗理由分布（金額は list rate 換算の注記付き補助） |
| 事前登録 | **「有意 / 優位 / 非劣性を主張しない」** |

**(14) 第三者評価パッケージ**

- 正規化転記＋UUID 匿名化ビューを決定論的に派生（運用用の方式露出命名は別に保持）
- **マッピング表の sha256 を採点開始前にコミット**
- 提示順ランダム化＋左右入替の二重提示
- 評価票に「どちらが多段方式だと思うか＋確信度」を1問入れて **Blinding Index を実測**
- 採点確定・封印後にマッピングと監査ログを開示する**二段構え**

> LLM 判定の位置バイアスは致命的（先頭選択率 **64.3%**・絶対リフト **+15.7pt**）。盲検は「仮定する」のではなく「測る」対象である。

## 6. 視点別の要点

### 6.1 technical（技術的実現性）

幹の見出しアンカー／部番号／行範囲の抽出コードと config スキーマ、`claude -p` の実フラグで固定できる範囲、中間成果物フォーマット、run_id 生成と二層ログ構造、共有層の薄さと grep ゲート — の5点を実機検証。`--tools ""` 下での擬似 `function_calls` テキスト混入という**副作用を唯一実測した視点**であり、「遮断成功の証拠は `permission_denials` 空ではなく `tool_use` 件数 0」という判定基準の訂正はここから来ている。

**未解決**: `--max-turns` が実際に指定 turn 数で打ち切るかは未検証 / 1MB〜10MB 級 stdin の Windows 安定性未実測 / `dontAsk` モードの read-only コマンド集合の正確な内容が一次未確認。

### 6.2 cost（コスト・リソース）

トークン見積り・キャッシュ・開発ループ節約・ログ容量・壁時計時間。**B/A 比を 1.08倍から 4〜7倍へ訂正**し、支配項が思考込み出力であることを特定した中心的視点。`--max-turns` を「2.1.220 に存在しない」と結論した点は誤り（`--help` grep 由来の偽陰性）だが、運用上の結論（turn 上限が現在付与されていない）は正しかった。

**未解決**: 実プロンプトの実測トークン数が未確定で金額は桁感にとどまる / effort レベル別の思考トークン実測量が不明（総額と所要時間の両方の支配項なのに最も不確か）/ 54 tok/s は第三者ベンチ値で `claude -p` 経由・日本語出力・xhigh effort での実効値は未検証 / Batch API（50%引き）の利用経路を確認できず。

### 6.3 risk（リスク・失敗モード）

**「最悪の失敗は壊れたと分からない経路に集中する」**という本調査の中核洞察を提供。incomplete-response 挙動（ストリーム途中失敗時に完了済み出力＋通知文を返す → exit code と非空チェックしか見ないと切断成果物が complete として確定する）を特定し、同型の穴3つ（schema フォールバックの静かな昇格 / 幹マッピングの腐敗 / 監査連鎖の断裂）を列挙。

**未解決**: `CLAUDE_CODE_MAX_OUTPUT_TOKENS` の既定値と A の打ち切りリスクの定量化 / incomplete-response 通知文の正確な文字列と構造判定フィールドの実値 / `dontAsk` + `--tools ""` の組合せ実測 / 本アカウントの session 枠・weekly 枠の実上限とリセット時刻 / 本タスク種別（長文生成）の試行間分散の実測値。

### 6.4 alternatives（代替案・競合）

**設計選択は外部の成熟事例が一貫して同じ形に収束する**ことを示した。

| 設計選択 | 収束先 | 先行事例 |
|---|---|---|
| 幹マッピング | **ハイブリッド**（人間可読キー＋正規化ハッシュ＋引用断片） | W3C Web Annotation のセレクタ併記 / Hypothesis の段階的再アンカー / SWHID の内在ハッシュ＋外在 qualifier / fiberplane-drift の AST fingerprint |

### 6.5 experiment_validity（実験妥当性・交絡制御）※動的視点

**この視点が本テーマの最も弱い環を特定した。**

| 論点 | 結論 |
|---|---|
| N の妥当性 | **N=3 では符号検定の最小両側 p=0.25 で有意性が原理的に到達不能**。記述的パイロットとしてのみ成立 |
| 不可視入力の混入 | `claude -p` は既定で CLAUDE.md（上位まで全連結）・`.claude/rules`・auto memory（先頭200行/25KB）・hooks・MCP を自動発見。**auto memory は git リポジトリ単位で全 worktree 共有**のため worktree 分離では独立性が確保されない |
| 対称性の検証 | 注入量の等価性ではなく**順守の等価性**で行うべき（両腕に同一の検証可能なダミー指示を植え、実際に効いていたかをプローブ） |
| 評価の盲検 | LLM 判定の位置バイアス（先頭選択率64.3%・絶対リフト+15.7pt）が致命的。**UUID 匿名化＋マッピング表ハッシュの採点前コミット＋提示順入替＋Blinding Index 実測**が必要 |
| 欠測メカニズム | ラン失敗は MAR とは限らない（予算超過は方式の呼出回数と相関＝**systematic missingness**）。単純な多重代入は不適切 |

**未解決**: N=3 相当の極小標本で許容される統計手法（ベイズ事後分布、ブートストラップ CI、同等性マージン）の具体的推奨を特定できず / 「指示強度」の定量尺度に関する確立した文献が見つからず（length-matched baseline までが限界）/ 第三者評価者の必要人数・評価者間一致度の要件は未調査。

### 6.6 harness_reuse（既存ハーネス資産の再利用可否）※動的視点

**既存資産の2つの実害バグを実測で特定した視点。**

| 資産 | 判定 | 根拠 |
|---|---|---|
| `common.sh` の `run_claude` | **ベンダリング（pin コピー）＋必須修正**。依存は不可 | 2802行・56関数・状態パス8本固定・毎呼出 `circuit-breaker.json` 再読込・直近2か月20コミット。参照すると実験がハーネス状態と改訂に晒される |
| コスト/トークン計上 | **実質死亡（実害バグ①）** | `extract_cost_from_debug_log` が `"input_tokens":` を grep するが直近6ログすべてでヒット 0 → 早期 return、`costs.jsonl` は 2026-07-14 の合成値で更新停止。セッション累計ブレーカーも実質死亡 |
| 予算超過分類 | **素通り（実害バグ②）** | 旧文言 `Exceeded USD budget` 依存だが実際は `exit 1` / `subtype=error_max_budget_usd`。`is_retryable` が真になり決定的失敗を再試行して支出を積み増す |
| フラグ実在プローブ | **偽陰性** | `--help` grep 方式が `--max-turns` / `--system-prompt-file` を存在しないと誤判定（argument-missing プローブで実在確認） |
| `.pending` の扱い | **証跡消失** | 失敗時に `rm` し、attempt スコープでないため再試行で前回証跡が消える |
| `simulator.sh` | **高価値・低結合。ほぼそのまま流用可** | 486行・`common.sh` 内部関数参照 0件・7故障種・回帰テスト同梱。`FORGE_DRY_RUN > fault > replay > real` |
| `validate_json` | **衛生器として限定利用** | リポに実 JSON Schema バリデータは存在せず、CRLF/フェンス衛生器であって型検証器ではない。ブレース抽出が「構文有効・スキーマ不適合」な JSON を昇格させる |

**未解決**: MSYS の `timeout`（SIGTERM）が `claude`(node) の子プロセスツリーまで確実に終了させるか未検証（`exit 124` 依存の分類がゾンビ残存で崩れる可能性）/ simulator の record→replay E2E を本 CLI バージョンで実走させていない / `icacls /T` 再帰適用および `references/` 全体への適用効果は未実測。

## 7. 視点間の矛盾と裁定（10件）

| # | 論点 | 対立 | 裁定 |
|---|---|---|---|
| 1 | **`--max-turns` の実在** | cost: help grep 0件で「存在しない」／technical: 隠しフラグと推定／harness_reuse: argument-missing で実在確定 | **フラグは実在**。cost の結論は誤りだが運用結論（turn 上限は現在付与されていない）は正しい。原因は `--help` grep の偽陰性 → **argument-missing プローブに置換**。ただしツールゼロ運用では turn 上限の必要性は低く、真のループ上限はツール遮断と外部タイムアウトに置く |
| 2 | **プロンプトキャッシュの TTL** | cost: サブスク1時間 / usage credits 5分／experiment_validity: 既定5分 | **矛盾ではなく認証方式による分岐**。本環境はサブスク OAuth なので1時間側の可能性が高いが、usage credits に落ちると5分。制御手段は存在しない → キャッシュを**「統制するもの」から「共変量として記録するもの」に格下げ**。並べ替え禁止。A は跨ぎキャッシュの恩恵を構造的に受けられないため**主指標は金額ではなく生トークン** |
| 3 | **`--bare` の採否** | experiment_validity: 両腕 `--bare` 固定を強く推奨／technical・harness_reuse: 実機で `Not logged in` | **理想解だが即採用不能**。等価な代替（`--system-prompt-file` + `--setting-sources ''` + `--strict-mcp-config` + `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` + CLAUDE.md 無し専用 cwd + `--no-session-persistence`）を明示的に組む。**「`--bare` と等価」とは主張せず**、段階0で差分ゼロをアサートし残差は脅威として報告 |
| 4 | **隔離の強度 vs 測定装置の同一性** | risk・technical: worktree/Docker の物理分離が確実／alternatives: ランナー複製は MMLU で順位逆転を招いた → 測定装置は共有 | **層が異なるため階層化して解消**。測定装置は単一実装を共有（交絡回避）、方式固有物のみ分離＋grep ゲート。実行時の相互参照は呼出層のツールゼロ化・cwd 限定・env allowlist・arm 別 TMPDIR で一次防御。物理分離は**サンドボックス運用としては推奨するが隔離の根拠を worktree に依存させない**（auto memory は全 worktree 共有） |
| 5 | **`--tools ""` の副作用** | technical: 擬似 `function_calls` テキストが本文に混入／alternatives・harness_reuse: exit 0 正常で副作用に言及なし | **矛盾ではなくプロンプト依存**（「ツールを使えと指示された場合」のみ発生）。① 全工程のプロンプトから読書指示を排除、② **成果物純度検査を確定ゲートに追加**、③ 遮断成功の証拠は `permission_denials` 空ではなく **`tool_use` 件数 0** |
| 6 | **per-call 予算の正規化方法** | cost: `per_call = R / K`／alternatives: 単発でも固定オーバーヘッド（cache_creation 23,694 tok・$0.1438）が乗るため `R/8` は B を過小配分 | `per_call = R/K + overhead_measured × 安全係数`。**真のラン上限はランナーが `total_cost_usd` を累積して強制**（厳密に揃える唯一の手段）。config に `scope: per_call \| per_run` を必須フィールドとして型付け |
| 7 | **必要試行数** | experiment_validity: K≧3テーマ × n≧2 の完全ペアが最低条件／risk: arm ごと n≧5（可能なら10）／ロック: 同一テーマで N≧3 | **ロックの N≧3 は下限であり上限ではない**と解釈（ロック変更ではない）。設計要件は「テーマ差し替え可能・同一テーマで N≧3 が必ず取れる」。実験計画としては K≧3 × n≧3（予算許容なら n=5）を推奨。**統計的主張は封じる** |

## 11. フォールバックと撤退判断

### 11.1 フォールバック（縮退）

**方針**: 成果物を「反証実験の完遂」から**「監査可能な生成システムの実証＋較正データの提出」**へ切り替える。

| # | 縮退内容 |
|---|---|
| (a) | テーマを1本に絞り n=3 のまま、A,B,B,A インターリーブと二重報告は維持 |
| (b) | 較正ランで A の出力上限・タイムアウト超過が確認された場合は arm 別にタイムアウトを正規化して再実行。それでも A が構造的に落ちるなら **A の出力長要求を B の最終成果物長に合わせて再宣言**してから較正をやり直す（**実装由来の不利は消す原則**） |
| (c) | クォータ枯渇が連続2ランを阻害する場合は effort を A/B 同時に1段下げて再宣言（不変条件の変更として manifest に記録）。それでも通らなければ **Haiku/Sonnet でのパイプライン健全性確認までを成果物として確定**し opus 本番は別セッションへ繰延 |
| (d) | エンベロープからコスト・トークンが取れない場合は主要指標を**完走率・所要時間・失敗理由分布・監査連鎖の遡及可能性のみ**に縮退 |
| (e) | 幹写像プリフライトが幹改訂で fail-closed して止まる場合は**実験期間中の幹凍結を優先**し、写像更新は実験外で人間承認を経て行う |
| (f) | 盲検が Blinding Index で破れていた場合は**方式ラベル開示前提の非盲検評価**として報告し、盲検不成立を明記 |

いずれの縮退も**「何を落としたか」を品質債務相当の台帳に必ず記録し、報告書に赤字で表面化させる**。

**根拠**: 本テーマの価値は「A/B のどちらが優れているかの結論」ではなく**「方式差を追跡可能な形で観測できる装置を持つこと」**にある。N が小さい以上、結論の強度は最初から限定されており、装置の完成と較正データ（per-call 実額、実効スループット、タイムアウト境界、失敗理由分布、幹写像の健全性）は次セッションで N を積み増す際にそのまま再利用できる。逆に**公平性が壊れた条件で N を積むと「測ったが解釈できないデータ」が残るだけ**で、コスト（1セット約$15・逐次2.5〜3時間）と時間の純損失になる。

### 11.2 縮退トリガー（いずれか観測時点で切替）

| # | トリガー |
|---|---|
| (a) | 較正ランで A が**出力上限到達 / exit 124 / incomplete 通知のいずれかを 2回中2回**発生させる |
| (b) | クォータ枯渇（exit 22 相当）または 429 の retry-after 待ちで**連続2ランが完了しない** |
| (c) | 1セットの実額が宣言 per_run 総額の **1.5倍を超える** |
| (d) | 確定ゲートで schema フォールバック・成果物純度違反・幹 sha256 不一致のいずれかが**全ランの3割超で発火** |
| (e) | エンベロープから `usage` / `total_cost_usd` / 実 `model_id` のいずれかが取得できない |
| (f) | 幹写像プリフライトが実験期間中に fail し人間承認なしでは解消できない |
| (g) | **Blinding Index が偶然水準を有意に超え盲検が破れている** |
| (h) | 較正段階で壁時計が想定（1セット3時間）の**2倍を超える見込み**になる |

### 11.3 撤退（非推奨）

撤退＝実験システムを構築せず、A/B のプロンプトを手作業で1回ずつ回して目視比較するにとどめる選択。これを支持する材料は実在する（N=3 で推論統計が原理的に不可能／公平性の非対称は完全に消せない／1セット約$15・2.5〜3時間に加えて実装と較正の工数が乗る）。

**しかし推奨しない。** 手動比較では監査要件（宣言文→台帳→本文→検査表→差分→最終の遡及）が原理的に満たせず、無人モードもテーマ差し替え再実行も成立しないため、**ロックされた完成条件のどれ一つも達成されない**。

**失うもの（機会費用）**:

| # | 内容 |
|---|---|
| 1 | **provenance** — 任意の最終出力から中間成果物の連鎖を遡る監査可能性。LLM は非決定的なので手作業では再構成不能 |
| 2 | **再実行性** — テーマ/ブリーフ差し替えによる再走ができず、将来 N を積む道も閉じる |
| 3 | **較正データ** — Opus 5 の per-call 実額、実効スループット（約54 tok/s）、タイムアウト境界、固定文脈オーバーヘッド、失敗理由分布 |
| 4 | **副産物のハーネス改善** — 本調査で実測特定した既存ハーネスの2つの実害バグ（コスト計上の沈黙死、予算超過分類の文言不一致による futile リトライと支出積み増し）、フラグ実在プローブの偽陰性、`--allowed-tools` を封じ込めと誤解する設計上の穴。撤退するとこれらの修正動機も失われ、**他プロジェクトでも同じコストを払い続けることになる** |
